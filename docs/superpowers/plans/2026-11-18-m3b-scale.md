# M3b — Scale Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** At the declared size (10 000 notes, about 100 MB), one change reaches another device in under 1 second, the engine's status stays truthful during long rounds, and the GUI stays responsive; plus the minors parked in M2 and M3.

**Architecture:** A load cache in `ns-core` makes every scan re-read only files whose size or modification time changed (git's racy rule for the rest). The sync engine scans through it and keeps its disk state between passes; the sync document keeps a cached view refreshed from the CRDT's own diff. A keeper thread keeps `status.json` fresh during long rounds. The GUI applies deltas to its index instead of rebuilding it, simulates the graph with Barnes–Hut, and virtualises the file tree.

**Tech Stack:** Rust 1.98+, `loro` 1.17 (`LoroDoc::diff`, `state_frontiers`), `egui` 0.37 (`ScrollArea::show_rows`), `std::fs::File::set_modified` in tests.

**Spec:** `docs/superpowers/specs/2026-11-15-second-brain-design.md` — sections 5.3 «Incremental scanning», 8.3 (`status.json`), 8.4 «Cached view», 8.5 step 1, 8.8 (`ns sync status`), 8.9 «Status (M3b)», 9.3, 9.4, 9.5, 11.2 «M3b».

## Global Constraints

1. Everything in Rust: no web/JS frontend, no other language in the product.
2. Notes are Markdown files; the product offers a graph view of the links.
3. Serverless P2P sync between devices, working between Windows and Linux (almost every distro). macOS excluded.
4. UI like Obsidian, not too complicated: very simple and minimal, very legible and accessible, polished, a little macOS-like with a glass effect.
5. Native access for AI agents (MCP, CLI, connectors for Claude).
6. The `.md` files on disk are the source of truth. Index, graph and sync state are derived and rebuildable.
7. One process per vault runs the sync engine (lock file). CLI and MCP write only files, never the sync state.
8. Every path coming from the CLI, MCP or a peer is validated and confined to the vault root before touching the disk.
9. No silent data loss: what sync removes goes to the vault's trash; a divergence becomes a conflict copy; an unreadable file is «blocked», never «absent»; creating a note never replaces an existing file.
10. The MCP server's stdout carries only protocol messages; logs go to stderr.
11. Code standards: `cargo fmt`, `cargo clippy --workspace --all-targets -- -D warnings`, doc comments on public APIs, no `unsafe`, no `unwrap()`/`expect()` outside tests, functions within 30 lines (clippy `too_many_lines`) and 4 parameters, Conventional Commits.
12. No new dependency in any crate. Test names: `should_<behaviour>`.
13. Racy window: exactly 3 seconds (`RACY_WINDOW`). Keeper interval: 5 seconds. Barnes–Hut opening angle θ = 0.8. Graph simulation limit: 10 000 nodes. Engine test waits: at most 30 seconds, no fixed sleeps.

## Review Focus

1. **A change the cache missed under a remote edit.** A file whose content changed while size and time did not (outside the racy window) receives a remote change: the replace must be refused (compare-before-overwrite re-reads the disk), the cache must forget the file, and the next round must take the local text into the document — never a key blocked for ever. Test in Task 3.
2. **The vault vanishing during a cached scan.** An unmounted vault must never read as «every note removed»: the marker checks stay around the scan, and a failing scan leaves the cache untouched. Tests in Tasks 2 and 3.
3. **A write in the same second as the read.** A file rewritten with the same size and the same modification time within 3 seconds of its last change must still be seen. Test in Task 2.
4. **The GUI's own save racing a background reload.** A delta computed before the save is discarded together with its cache; an external edit made before the save must still reach the index afterwards. Test in Task 6.
5. **A partial import.** Updates whose history is incomplete (pending) are imported: the cached view must still equal a view computed from scratch, before and after the missing history arrives. Test in Task 4.

**Interfaces:**
- Produces (used by Tasks 3 and 6):

```rust
pub const RACY_WINDOW: Duration = Duration::from_secs(3);

/// What the previous scans saw, per note file (spec 5.3). Cheap to clone.
#[derive(Debug, Default, Clone)]
pub struct LoadCache { /* private */ }

/// What changed since the previous scan with the same cache.
#[derive(Debug, Default, PartialEq, Eq)]
pub struct LoadDelta {
    /// Notes that are new or may have changed, with on-disk spelling and content, ordered by key.
    /// A spelling-only change appears here, never in `removed`.
    pub changed: Vec<(NotePath, String)>,
    /// Notes of the previous scan whose key is no longer a note (gone, or now ignored), ordered by key.
    pub removed: Vec<NoteKey>,
    /// Every ignored file of this scan, exactly as `Vault::load` reports them.
    pub ignored: Vec<Ignored>,
}

impl LoadCache {
    /// The next scan reads this note's file again, whatever its size and time.
    pub fn forget(&mut self, key: &NoteKey);
}

impl Vault {
    /// Scans like `load`, reading only files that may have changed (spec 5.3).
    /// # Errors
    /// `Io` when the root cannot be listed; the cache is then unchanged.
    pub fn load_changes(&self, cache: &mut LoadCache) -> Result<LoadDelta>;
}
```

Rules (spec 5.3): size and time from `DirEntry::metadata()`; re-read when the spelling, size or `modified()` differs, when new, or when racy (`modified + RACY_WINDOW > read_at`, `read_at` taken just before the read); `TooLarge` from the size; `NotUtf8` cached by size and time; `Unreadable` never cached; a file whose metadata cannot be had is read as today. The case-collision winner is decided on the full listing every scan.
