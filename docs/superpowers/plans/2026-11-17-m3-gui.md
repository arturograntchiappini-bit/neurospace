# M3 — Desktop GUI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `secondbrain`, a desktop window in the spirit of Obsidian — very simple, very legible, a little like macOS with glass — to open a vault, write and link notes, search, see the graph and run sync, built on the M1 core and the M2 engine.

**Architecture:** A new crate `sb-app` (library `sb_app` plus binary `secondbrain`). `src/state/` holds every behaviour and never imports egui: it is unit-tested on real temporary vaults. `src/ui/` draws that state with `eframe`/`egui` 0.37 and forwards input; `egui_kittest` drives the real UI code headless. Slow work (loading the vault, sync engine calls) runs on background threads that answer over channels and wake the UI. Two small additions land first in `sb-core` (note creation, attachment links, the path of a note created from a link) and `sb-sync` (saving `config.json`).

**Tech Stack:** Rust 1.99 (edition 2024), `eframe` 0.37, `egui_commonmark` 0.26, `rfd` 0.18, `egui_kittest` 0.37 (tests), `window-vibrancy` 0.8.1 (Windows only), Inter 4.1, plus what M1 and M2 already use.

**Spec:** `docs/superpowers/specs/2026-11-15-second-brain-design.md` — sections 6.1, 6.3 and 6.6 (link rules added for M3), 9 (GUI, with 9.6 visual design and accessibility), 11.2 M3 (acceptance), appendices A.3 (egui facts) and A.5 (glass spike facts). Section numbers below refer to it.

**Out of scope, moved to plan M3b (after this plan, before M4):** the sync-engine performance work (incremental scan, cached document view, status written during long rounds; target: one change reaches the other device in under 1 s at 10 000 notes) and the five status minors deferred from M2. They change the engine, not the GUI. The GUI shows the engine's status as it is today.

## Global Constraints

- Rust only. Edition 2024. No `unsafe` anywhere in our code (`unsafe_code = "forbid"`); `window-vibrancy`'s own unsafe stays inside that crate.
- No `unwrap()`, `expect()` or `panic!` outside tests. Errors are values; the GUI shows them, it never crashes on them.
- Every public item has a doc comment (`missing_docs` is on). Functions at or under 30 lines and 4 parameters (`clippy.toml`).
- Before every commit all three pass with no warnings: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`.
- Test names follow `should_<expected>_when_<condition>`. Commits follow Conventional Commits.
- **The files are the truth.** The GUI reads and writes notes only through `sb_core::ops` and `sb_core::Vault`. Every path typed by the user goes through `NotePath::parse` (inside `ops`) before any disk access.
- **No silent data loss.** Delete moves to the vault's trash. Creating a note never replaces anything. Typed text is never dropped: a failed save keeps the buffer dirty; an external change or removal of a note with unsaved edits writes the buffer to a conflict note (spec 9.3).
- **The engine runs only when sync is configured** for the open vault or the user asks for it in the sync window (spec 9.5). A vault that never used sync never contacts the network.
- **The UI thread never blocks** on: opening or reloading a vault (`Index::build`), any `EngineHandle` call, starting or stopping the engine. Reading or writing one note, and the native folder dialog, may run on the UI thread.
- `src/state/` never imports `eframe`, `egui` or any other UI crate. A test in Task 2 enforces this.
- Colours, fonts, radii and shadows come only from `src/ui/theme.rs`, whose tokens are the table of spec 9.6, exactly. No colour literal anywhere else in `src/ui/`.
- Accessibility (spec 9.6) applies to every UI task: every text field has a label or hint text (`egui_kittest` fails a test otherwise), every button showing only a symbol carries an accessible name, every action is reachable by keyboard, nothing is conveyed by colour alone.
- Tests never start the real sync engine and never touch the network or the real state and settings directories: they use temporary directories and the fake `SyncControl` of Task 9.
- Dependencies, exactly as follows and no others. In `crates/sb-app/Cargo.toml`: `eframe = { version = "0.37", default-features = false, features = ["default_fonts", "glow", "x11", "wayland", "clipboard", "links", "accesskit"] }`; `egui_commonmark = { version = "0.26", default-features = false, features = ["pulldown_cmark"] }`; `rfd = { version = "0.18", default-features = false, features = ["xdg-portal", "wayland"] }`; `clap`, `serde`, `serde_json` from the workspace; `sb-core` and `sb-sync` by path; `[target.'cfg(windows)'.dependencies] window-vibrancy = "0.8.1"`; dev: `egui_kittest = "0.37"`, `tempfile` from the workspace. egui is used as `eframe::egui`, never as its own dependency.
- `README.md` and `CHANGELOG.md` are updated by the task that adds a user-visible feature.
- Line endings LF. Code behaves the same on Windows and Linux. The orchestrator runs the suite in the Linux container before marking a task that touches files or threads complete.
- M1/M2 facts every task may rely on: `sb_core::ops::{list_notes, read_note, write_note, append_to_note, delete_note, rename_note, search_notes, get_links, get_graph, list_tags}`; `WriteOutcome { path: NotePath, created: bool }`; `Index::{build, from_notes, upsert, remove, get, notes, len, ignored, resolve(target, from), outgoing(key), backlinks(key), tags(), graph(), search(query, limit)}`; `NotePath::{parse, as_str, key, stem, folder, components}`; `Vault::{open, root, load, locate, adopt_folders, read, write, create, delete, rename}`; `sb_core::watch(root, impl Fn() + Send + 'static) -> Result<VaultWatcher>` gives a signal only, no paths, and stops when the `VaultWatcher` is dropped; `sb_sync::{start_engine(vault_root, StateDir, Option<Sender<EngineEvent>>) -> Result<EngineHandle>` (call it from a plain thread, never inside a tokio runtime), `EngineHandle::{invite, join, leave, status, request_status, is_running, shutdown}` (`invite`, `join`, `leave`, `status` block up to 10 s), `EngineEvent::{PeerConnected, PeerDisconnected, Synced, Blocked, Error, Notice, Stopped}`, `StateDir::{for_vault_in(base, vault_root), secret, config, read_status}`, `control::status(state, now_unix) -> Result<Option<Status>>`, `Status { device_id, addresses, peers: Vec<PeerStatus { id, connected }>, notes, blocked: Vec<BlockedNote { path, reason }>, relay, last_error, .. }`, `NetConfig { mode: NetMode::{Internet, Lan}, bind_port, mdns }`, `SyncError::AlreadyRunning`, `base_dir_from(windows, env)`, `random_bytes::<N>()`, `to_hex`}.

## Review Focus

Failure modes the spec implies and that are most likely to bite a user. Each has a test in the task that owns the code.

1. **A vault reload that started before a save finishes after it.** Expected: the stale index is not used to judge the open note — no reverted buffer, no spurious conflict copy; another reload follows. → Task 4.
2. **A save fails** (the note was made read-only, its folder vanished). Expected: the buffer stays as typed and dirty, the status strip shows the error, the next autosave trigger retries. → Task 3.
3. **An unresolved link that cannot become a note** (`[[a:b]]`, `[[../../x]]` with `./`, `[[CON]]`, `![[photo.png]]`). Expected: no file is created, the status strip says why, the app keeps working. → Task 1, Task 7.
4. **The vault folder disappears while open** (USB stick unplugged). Expected: the reload fails, the last index stays, the open buffer stays, an error is shown, nothing crashes; later saves fail visibly. → Task 4.
5. **An engine call takes long or fails** (invite while the network is down: up to 10 s, then an error). Expected: the window stays responsive, the action shows «in progress», then the error. → Task 9.

  - `workspace.rs`:
    - `pub const AUTOSAVE_DELAY: Duration = Duration::from_millis(500);` `pub const QUICK_OPEN_LIMIT: usize = 50;`
    - `#[derive(Debug)] pub struct OpenNote { pub path: NotePath, pub buffer: String, pub saved: String, pub last_edit: Option<Instant> }` — `last_edit` is `Some` while the buffer differs from what is on disk; `pub fn is_dirty(&self) -> bool`.
    - `pub struct Workspace` with private fields `vault: Vault`, `index: Index`, `tree: Folder`, `open: Option<OpenNote>`, `save_generation: u64`.
    - `impl Workspace`:
      - `pub fn open(root: &Path) -> sb_core::Result<Workspace>` — `Vault::open` + `Index::build` (blocking; the UI calls it on a background thread).
      - `pub fn vault(&self) -> &Vault`, `pub fn index(&self) -> &Index`, `pub fn tree(&self) -> &Folder`, `pub fn open_note(&self) -> Option<&OpenNote>`, `pub fn save_generation(&self) -> u64`.
      - `pub fn select(&mut self, path: &NotePath) -> sb_core::Result<()>` — saves a dirty open note first (an error stops the switch), then reads the note with `ops::read_note`.
      - `pub fn close(&mut self) -> sb_core::Result<()>` — saves if dirty, then closes.
      - `pub fn edit(&mut self, text: String, now: Instant)` — replaces the buffer; `last_edit = Some(now)` when it differs from `saved`, `None` when equal.
      - `pub fn autosave_due(&self, now: Instant) -> bool` — dirty and `now - last_edit >= AUTOSAVE_DELAY`.
      - `#[derive(Debug, PartialEq, Eq)] pub enum Saved { Nothing, Written, ChangedOnDisk }`; `pub fn save(&mut self) -> sb_core::Result<Saved>` — `Nothing` when clean. Otherwise a **compare-and-swap**: `vault.locate` the note, then `vault.replace_if(path, buffer, |bytes| bytes == saved.as_bytes())`. Replaced → `saved = buffer`, `last_edit = None`, `index.upsert`, `save_generation += 1`, `Written`. Disk content differs from `saved`, or the note is gone (`locate` → `None` or `NotFound`) → `ChangedOnDisk`: nothing is written, never recreated, buffer stays dirty; Task 4's reload then keeps the edits in a conflict note. Any other error is returned with buffer and dirty flag untouched (Review Focus 2). After `ChangedOnDisk` or an error, `autosave_due` stays false until the next `edit` (spec 9.3: retried at the next autosave trigger, not every frame). `select`, `close`, `rename` of the open note, `create` and `follow_link` save first and stop with `CoreError::InvalidInput("<path> changed on disk; it will reload in a moment")` on `ChangedOnDisk`. (Revision 2026-11-17 after Task 3: an unconditional `write_note` would silently replace a remote edit that sync wrote moments before an autosave.)
      - `pub fn create(&mut self, name: &str, folder: Option<&str>) -> sb_core::Result<NotePath>` — `name` trimmed, `.md` appended unless present (ASCII case-insensitive), joined under `folder`; `ops::create_note` with empty content; index and tree updated; the new note is selected.
      - `pub fn rename(&mut self, from: &NotePath, to: &str) -> sb_core::Result<NotePath>` — saves first if `from` is open and dirty; `.md` appended to `to` unless present; `ops::rename_note`; index, tree and the open note's path updated.
      - `pub fn delete(&mut self, path: &NotePath) -> sb_core::Result<()>` — `ops::delete_note` (to the trash); closes it without saving if open; index and tree updated.
      - `pub fn follow_link(&mut self, target: &str) -> sb_core::Result<NotePath>` — from the open note: `index.resolve` → select it; unresolved → `new_note_path` (attachments and invalid targets return its error, nothing is created) → `create` with that exact path → select it.
      - `pub fn quick_open(&self, query: &str) -> Vec<NotePath>` — empty query → empty; otherwise notes whose lowercase path contains the lowercase query; stems starting with the query first, then by path; at most `QUICK_OPEN_LIMIT`.
      - `pub fn search(&self, query: &str) -> Vec<SearchHit>` — `index.search(query, DEFAULT_SEARCH_LIMIT)`.
      - `pub fn word_count(&self) -> usize` — `split_whitespace().count()` of the open buffer, 0 when none.

    - `pub fn mark_changed(&mut self, now: Instant)` — also used by tests instead of real events.
    - `pub fn tick(&mut self, workspace: &mut Workspace, now: Instant) -> Vec<Notice>` — if a change is pending, `now - last change >= RELOAD_DEBOUNCE` and no job runs: spawn `Index::build` on a clone of the vault root, tagged with `workspace.save_generation()`.   - `impl Workspace { pub fn apply_index(&mut self, index: Index, started_at_save: u64) -> ApplyOutcome }` with `pub enum ApplyOutcome { Applied(Vec<Notice>), Stale }` — `Stale` when `save_generation() != started_at_save`: the index is dropped and the caller marks a new change (Review Focus 1). Otherwise swaps the index, rebuilds the tree and reconciles the open note by comparing the new index's content for its key with `saved`:
    - present and equal → nothing;
    - present and different, clean → `buffer = saved = new content`, no notice;
    - present and different, dirty → the buffer is written with `ops::create_note` to `<folder>/<stem> (conflict <8 hex>).md` (hex from `sb_sync::random_bytes::<4>()` and `to_hex`), then `buffer = saved = new content`; `Notice::info("Your unsaved edits to <path> were kept in <conflict path>")`;
    - absent, clean → close; `Notice::info("<path> was removed or can no longer be read")`;
    - absent, dirty → conflict note as above, which becomes the open note; `Notice::info(...)` naming it.
    - If writing the conflict note fails, the buffer stays open and dirty and `Notice::error` says so: text is never dropped.

    - `pub struct SyncPanel` — the window's model: `pub enum SyncState { Off, Starting, On, HandledElsewhere, Error(String) }` (initially `Starting`), `pub busy: Option<&'static str>` («Creating invite…», «Joining…», «Turning sync off…», «Switching mode…»), the last ticket, the join field text, the last `Status`; `pub fn request(&mut self, worker: &SyncWorker, request: Request)` (sends it and sets `busy`); `pub fn apply(&mut self, reply: Reply)`; `pub fn summary(&self) -> String` for the status strip: «Sync off», «Sync starting…», «Sync: <n> of <m> peers online», «Sync handled by another process», «Sync error».
  - `sync_control.rs` (the only production `SyncControl`): `pub struct EngineControl { vault_root: PathBuf, state: StateDir, handle: Option<EngineHandle> }` using `start_engine` (from the worker thread, which is a plain thread), `EngineHandle::{invite, join, leave, status, shutdown}`, `control::status` for `HandledElsewhere`. Engine events are not needed: the panel refreshes status every 2 s while the window is open and every 10 s otherwise, through `RefreshStatus`.
